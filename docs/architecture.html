ZainCash Support Pipeline

Local back-office pipeline. Classify, extract, match the transaction, route, then a person approves.

Jev proposal

  • One call proposes the category, urgency as P1–P4, and six flags.
  • Flags: fraud, money lost, several issues, anger or urgency, a named transaction, asks for a person.
  • A second call repeats only the category, with the options reversed.
  • Uncertain if the label is invalid, the top probability is under 0.60, confidence is under 0.60, or those two category calls disagree.
  • Cascade mode then asks Gemini. Jev-only mode does not. A Jev failure in cascade mode does too.

Three samples

  • The same prompt runs three times, in parallel, at temperature 0.7.
  • Category is the label that appears most. Confidence is that count divided by 3, so a failed call lowers it.
  • Urgency is the majority among the runs that picked the winning category.
  • Each flag is the share of successful runs that said yes. Above 0.5 it counts.
  • Agreement under 0.66 is uncertain. Two of three is the minimum.
  • A disagreement is escalated when Jev was at least 0.40 confident on its category.

Safety

  • Card numbers are masked before anything is stored.
  • An extracted value must appear in the ticket text.
  • Fraud, missing details, and transaction mismatches escalate.
  • The agent copies an approved reply. The system never sends it.

Runtime

  • Vite on :5173 proxies /api to uvicorn on :8000.
  • The CLI and the UI call the same LangGraph graph. Concurrency 20, retry ×3.
  • Postgres is Docker pgvector on host :5433. Schema is support.
  • Drafting is still NullDrafter. Plan 3 replaces it with a cited RAG agent.
